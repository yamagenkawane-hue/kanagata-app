# 現在のPCでのテスト運用（2026-11-13）

## 対象と開始条件

現在のPC上で、少量の試験用金型を使って金型登録 → BOM → 日程作成・保存 → 実績入力 → 進捗確認を行う。実データのDBに接続するため、試験用の金型名は「試験_」から始め、既存の業務データと区別する。

この段階では社内LAN公開・インターネット公開を行わない。Node.js 26.13.0、Next.js 16.4.5を使用する。

## 起動・終了

プロジェクトのフォルダーでPowerShellを開き、次を実行する。

```powershell
npm ci
npm run pilot
```

`npm run pilot` は本番ビルドを作成してから、127.0.0.1:3000でサーバーを起動する。Readyが表示されたら [ログイン](http://127.0.0.1:3000/login) を開く。起動したPowerShellを閉じず、終了する際はCtrl+Cを押す。ポートが使用中の場合は、同じアプリの起動済みターミナルで終了してから再実行する。他のシステムを勝手に停止しない。

デモ用のadmin/adminは実DBにログインしない。普段の業務ユーザーを使用する。認証情報や `.env.local` の内容は共有しない。

## 追加した運用機能

- ガントと管理画面に「運用確認」とログアウトへの導線を追加した。
- [運用確認](http://127.0.0.1:3000/workspace/readiness) はDB読み取りだけを行い、日程を自動変更しない。
- 本日から31日間のカレンダー、3か月先の設定、有効な機械、時間重複、工程の欠落、BOM数量超過、プレート寸法、管理者・担当者数を確認する。
- 管理者は運用確認画面から金型・BOM・ロット・予定・実績などのスナップショットをJSONで書き出せる。パスワード・接続キーは含めない。
- この書き出しは、利用者アカウント・監査テーブル・削除済み実績などを含むDB全体のバックアップではない。アプリからの自動復元には非対応。DB復旧には別途Supabase側のバックアップ・復旧手順が必要。

新規のDBマイグレーションは不要。書き出しAPIは管理者だけに許可し、未ログインの取得は拒否する。

## 試験シナリオ

最初に運用確認の「要対応」を解消し、業務データを書き出す。その後に以下を実施する。

| 優先度 | 確認すること | 合格条件 |
| --- | --- | --- |
| Critical | 業務ユーザーのログイン | ログイン画面へ戻らずガントを表示できる |
| Critical | 金型・BOM | 試験用金型で一括登録を選び、共通サイズからPB・PP・SB・SP・DB1・DP各1枚を保存できる |
| Critical | 予定登録・再読込 | 必要工程の日程を作成・保存し、再読込後も表示される |
| Critical | 実績登録・修正 | 開始・終了時刻がガントと実績一覧に反映され、対象だけが完了になる |
| Critical | 担当者の権限 | 担当者は実績入力・修正ができ、予定・マスター設定の保存はできない |
| High | 機械変更 | ワイヤー1→2へ移し、異なる機械では同時加工できる |
| High | 順番変更 | ドラッグ後の保存でガントと未着手の後工程へ反映される |
| High | 重複解消 | 管理者が優先プレートを選び、後順位の実績・履歴・後工程が整合する |
| High | 閲覧 | 金型別／機械別切替、全工程表示、金型詳細、カード一覧へ移動できる |
| High | Excelカレンダー | 読み取り結果と元Excelの休日数を照合してから保存できる |
| High | ログアウト | 画面上のボタンでログアウト後、DB画面は再ログインが必要になる |

テスト実施後は試験用の未着手予定を取消・非表示にする。実績を登録したタスクは監査の対象なので、検証記録を残す。既存データの一括削除やDB初期化は行わない。

## 自動調整と注意事項

管理者がガントを開いた時と、その後の定期確認で、終了を過ぎた未着手予定を自動調整・保存する。ガントを開くこと自体が予定更新の契機になる。単にデータを確認したい場合は運用確認画面を直接開く。

保存結果を確認できなかった場合は再送せず、再読み込みして登録済みか確認する。複数人が同時変更した場合も、最新データを読み直してやり直す。

## 未実装・対象外

- 型組用／予備用の用途別ロット分割と、予備用を型組の依存条件から除外する機能は未実装。現行の型組は同じ金型の加工ロット全体の完了を待つ。予備部品を含む金型の型組開始判定は、今回の試験対象外とする。
- 実績データからの所要時間の自動推定は未実装。寸法と編集可能な概算時間を使用する。
- PCを閉じている間の自動調整、社内の他PCからの接続、常時稼働サーバー、DBの自動復元は今回の対象外。

未実装事項を含む本運用への移行は、この試験結果を確認してから判断する。


型生成が競合するため、typecheckとbuildは同時に走らせない。
サーバーを起動した別のPowerShellから `npm run test:smoke` で、実データを書き換えないHTTP確認を行える。

## 実装上の構成

`pilot-readiness.ts` がPlanDataに対する診断を計算し、`pilot-status.tsx` が表示する。`/workspace/readiness` は通常の業務認証とDB読取を使用する。`GET /api/business/export` はサーバー側で管理者権限を再確認してダウンロード応答を返す。通常の予定・実績APIの計算仕様、DBスキーマ、既存ユーザーの権限は変更していない。

## 次の確認

現在のPCで管理者による少量の試験を開始できる。担当者アカウントの作成、実画面の登録・編集・ドラッグ・カレンダー取り込み・書き出しの受入試験は未完了。これらの確認が済むまで、全業務の置き換えや本運用の完了とは扱わない。
