# 金型生産管理システム 要件まとめ

版: 1.0 / 作成日: 2026-10-01（日本時間） / フェーズ: requirements

本書は、これまでの回答と追加要件を統合した最新版。旧要件定義書・設計書は履歴として保持する。本書の要件がすべて実装済みという意味ではない。

## 1. 目的・利用環境

- 金型・プレート・パーツの生産予定、設備の加工順、担当者の実績を一元管理する。
- PCで利用し、想定利用者は約10名。
- Next.js、TypeScript、Supabaseを使用する。
- メールアドレス・パスワードで個別にログインする。
- 業務データはDBから取得し、登録・編集・削除を保存する。再読み込みでも保持する。

## 2. 管理単位と登録情報

製品1件を金型1件として扱う。別の金型管理番号・金型名という独立項目は設けない。

| 対象 | 登録情報 |
| --- | --- |
| 金型（製品） | 製品名、取引先、納期、備考 |
| BOM項目 | 名称、区分（プレート／パーツ）、必要数量、備考 |
| ガント登録 | 対象金型、BOM項目、今回の製作数量、必要工程の設備・担当者・所要時間・開始条件 |

製品名・納期・項目名・数量は必須。取引先・備考は任意。BOMには図番を設けない。

## 3. BOM

- 金型ごとに必要なプレート・パーツを登録するBOM設定画面を追加する。
- BOM項目を登録・編集・非表示にできる。
- プレートは全5工程を対象とする。
- パーツは項目ごとに必要工程を選択する。
- 設備・担当者・所要時間はガント登録時に入力する。
- ガントへ追加する際は、金型を指定して、そのBOMの項目を選択し、1件ずつ登録する。
- 同じBOM項目を数量分割して複数件登録できる。
- BOMの必要数量、ガント登録済み数量、未登録数量を表示する。
- 合計登録数量がBOMの必要数量を超える登録は禁止する。現段階では超過した追加製作を扱わない。
- BOM変更で登録済み予定・過去実績を自動的に書き換えない。

例: 必要数量4のパーツは、製作数量2の予定を2件登録できる。合計4となった後は追加登録できない。

## 4. 工程と設備

工程の標準順序は次のとおり。

1. マシニング
2. 自動研磨
3. ワイヤー
4. 型組
5. トライ

プレートは全工程。パーツは選択した工程をこの順序で実施する。工程の繰り返しや任意の順序変更は扱わない。
ワイヤー設備は4台を表示する。その他の設備名称・台数は実データ登録時に確認する。

## 5. 画面構成と遷移

| 画面 | 主な機能 |
| --- | --- |
| 生産計画トップ | 金型別ガント、パーツ名のバー表示、期間切替、検索・絞り込み、予定追加、再計算 |
| 金型詳細 | 金型情報、BOM・パーツ・工程予定の確認、編集・非表示 |
| BOM設定 | 金型別のプレート・パーツ、数量、必要工程の設定 |
| 工程詳細 | 指定工程の予定を金型別に表示するガント |
| 機械詳細 | 指定機械の加工予定、パーツ加工順、予定編集 |
| 実績入力 | 作業者、状態、開始・終了、作業時間、実績の編集・削除 |
| 設備管理 | 設備の一覧・登録・編集・使用停止 |
| ユーザー設定 | 管理者／担当者の役割変更 |
| 会社カレンダー | 稼働日・休日表示、Excel取り込み、設定変更 |

- トップは金型別を基本とする。設備別の詳細は別画面へ遷移する。
- 工程名をクリックすると指定工程の金型別ガントへ遷移する。
- 機械名をクリックすると該当機械の詳細画面へ遷移する。
- 各画面に関連画面へのリンクと戻る導線を設ける。
- 必要な箇所に登録・編集・削除ボタンを配置し、権限に合わせて操作可能にする。
- 「順位」ではなく「加工順」と明記し、どの機械の順番か分かるようにする。
- トップは必要情報を整理して、金型・パーツ・予定を把握しやすくする。

## 6. 日程・ガント・加工順

- ガントの基本時間軸は日ごと、目盛りは30分刻み。広い期間ではラベルを間引いて見やすくする。
- 所要時間は30分単位、開始・終了日時は1分単位。
- バーの文字は工程名ではなく、パンチプレートなどのプレート・パーツ名。
- 工程は色や行・詳細表示で識別できるようにする。
- 設備ごとに未着手タスクを1・2・3…の加工順で管理する。金型内の工程順序とは別のもの。
- 飛び込みタスクを途中に挿入でき、後ろの加工順を振り直す。
- 開始条件、所要時間、前工程の終了、設備の空き時間、会社カレンダーから後工程の日程を自動計算する。
- 自動計算では設備重複を避けて空き時間へ移動する。
- 管理者は警告を確認した上で、手動で重複する予定にも変更できる。
- 自動調整の対象は未着手かつ固定されていない予定。作業中・完了済み・固定予定は維持する。
- 変更前後の日程と納期超過を提示し、管理者が確認して確定する。

## 7. 稼働時間と会社カレンダー

| 項目 | 時間・方式 |
| --- | --- |
| 勤務時間 | 8:50〜17:40 |
| 昼休み | 12:00〜12:50 |
| 休憩 | 15:00〜15:10 |
| 通常の実働 | 1日7時間50分（470分） |
| 稼働日・休日 | 会社カレンダーに全日を設定 |
| 取り込み | Excelファイルを選択して取り込む |

- 定期的な自動取り込みは不要。
- Excelの列構成・日付・稼働日表現は実ファイルを確認して対応方法を設計する。
- 通常は勤務時間と会社カレンダー内で日程を計算する。
- マシニング・自動研磨・ワイヤーは、タスクごとに夜間稼働を指定できる。
- 夜間指定タスクは休憩・夜間・休日も連続して設備を稼働できる。
- 休憩中も設備を動かせる条件を設定できる。

## 8. 実績

- 状態は未着手・作業中・完了。進捗率は不要。
- 実際の作業者と作業開始・終了時刻を入力する。
- 休憩を除いた作業時間を自動計算し、必要に応じて修正できる。
- 日ごとの作業時間を記録・確認する。
- 担当者も他の担当者の実績を入力・修正できる。
- 実績の削除は管理者に限定する。
- 実績時刻の重複は警告を確認すれば保存可能。時間修正理由は任意。
- 過去実績の休憩設定を保持し、カレンダー変更で暗黙に再計算しない。
- 実績入力に合わせて残りの予定と後工程を空き時間へ組み直す。実績の時刻自体は動かさない。
- 実績保存と日程確定を分け、変更後の日程は管理者が確認する。
- 人の作業時間と設備の無人稼働時間を区別する。

## 9. 権限と削除

| 操作 | 管理者 | 工程担当者 |
| --- | --- | --- |
| 計画の登録・変更・加工順変更・確定 | 可 | 不可 |
| 自分・他の担当者の実績入力・修正 | 可 | 可 |
| 実績削除 | 可 | 不可 |
| 管理者／担当者の役割変更 | 可（管理者限定案） | 不可（案） |

- 金型・パーツ・設備の削除は、履歴を残す非表示・使用停止方式。
- BOM項目も非表示で履歴との関連を保持する。
- 画面のボタン制御に加えて、サーバー・DB側でも権限を検証する。
- 役割を変更する機能は確定。役割変更の実行者を管理者に限定する点は、先に提示した案として設計時に確認する。
- BOM・設備・カレンダーの変更権限と実績削除の履歴保存方式は設計で具体化する。

## 10. DB・テストデータ・品質

- Supabaseへ業務データを保存し、画面はDBから取得する。
- 金型・BOM・プレート・パーツ・設備・予定・実績などのテストデータを登録し、実データと区別する。
- テストデータにワイヤー4台とパーツ名の例を含める。
- 登録・編集・削除、ページ遷移、再読み込み後の保持を検証する。
- 加工順・数量上限・工程選択・夜間・休憩・固定予定・実績反映の正常系と異常系を検証する。
- 権限、DB整合性、同時更新と日程変更確定を検証する。
- 編集後は内容に応じた確認を行い、コミット・GitHubへのプッシュまで実施する。
- 接続キー、認証情報、環境変数はプッシュしない。

## 11. 優先度と今回の対象外

Must: DB取得・保存、画面遷移、BOM、数量内の分割登録、工程選択、ワイヤー4台、加工順、予定と実績、権限制御、非表示・使用停止、Excelファイル取り込み、テストデータと検証。

今回の対象外: 定期Excel取り込み、必要数量を超える追加製作、進捗率入力、工程の繰り返し・任意順序変更、スマートフォン対応。

## 12. 以前の要件からの変更

| 以前 | 最新要件 |
| --- | --- |
| 全パーツ必ず5工程 | プレートは全5工程、パーツは必要工程を選択 |
| パーツに図番 | BOM項目には図番不要。既存図番データの扱いは移行設計で決める |
| 会社カレンダーの自動取り込み案 | Excelファイルを選択する方式。定期自動取り込み不要 |
| デモ中心の画面 | DBデータで動く画面とページ遷移・CRUDを必要とする |
| 製品・パーツの直接追加 | 金型のBOMから選択し、数量内で1件ずつガント登録 |

## 13. 未確定・残確認

- Excel実ファイルの形式・列・稼働日表現。現物確認後に取り込み設計する。
- 実際の設備名、ワイヤー以外の台数、利用者情報。
- ユーザーの役割変更を実行できる権限の最終確認（管理者限定を提案済み）。
- 必要数量の変更、登録取消・非表示による数量戻し、作業済み項目の扱いを設計で具体化する。
- BOM変更時の既存予定との対応、旧図番の移行、実績削除の履歴方式。
- リモートSQL適用・テストに使う管理接続方法。認証情報はチャットに貼らない。

## 14. 実装との区別

初期デモ、固定5工程の計算、認証接続コード、初期SQLは作成済み。
追加要件のBOM・工程選択・DB CRUD・詳細ページ遷移などは未実装。初期SQLのリモート適用と実DB結合テストも未完了。
旧スケジューラーと初期スキーマをそのまま最新要件対応と見なさず、設計の追加版を作成してから改修する。
