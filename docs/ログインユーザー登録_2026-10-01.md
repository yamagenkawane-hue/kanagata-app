# ログインユーザー登録画面

## 要件・設計

ユーザー設定で表示名・メール・パスワード・権限を入力してAuthアカウントと業務プロフィールを作成する。UUIDの手入力を不要にする。通常の登録は有効な管理者だけが実行できる。
最初の管理者は`/setup`で登録する。24文字以上のサーバー設定の合言葉を必要とし、プロフィールが1件でも存在すると閉鎖する。DBの行ロックにより同時登録でも初回管理者は1件のみ。
メール送信は行わず、作成時にメール確認済みとして登録する。管理者がメールを確認して登録する社内運用を前提とする。既存ユーザーのパスワード変更・メール変更は今回の対象外。

## 設定手順

1. `.env.local`に以下を追加（実値はチャットやGitに入れない）。

```dotenv
SUPABASE_SECRET_KEY=Supabaseのサーバー専用Secret_key
INITIAL_ADMIN_SETUP_TOKEN=任意の24文字以上の合言葉
```

従来のservice_roleキーを使う場合は`SUPABASE_SERVICE_ROLE_KEY`でもよい。これらに`NEXT_PUBLIC_`は付けない。Secret keyはサーバー側だけで使用する。

2. SQL Editorで`supabase/migrations/202610010002_login_users.sql`を1回適用する（以前の2ファイルを再実行しない）。
3. アプリを再起動する。
4. ログイン画面の「初めて使う方：管理者を登録」から合言葉・表示名・メール・パスワードを入力する。
5. 登録後、メール・パスワードでログインする。初回合言葉は環境設定から削除してよい。
6. ユーザー設定の「利用者を登録」で追加ユーザーを登録する。

## 保存と制約

サーバーは認証・権限・Origin・入力サイズと形式を確認し、Auth Admin APIでアカウントを作成する。追加SQLはservice_roleだけに実行を許可し、登録直前に管理者権限・revisionまたは初回条件を再確認してプロフィール・監査ログを保存する。
DB登録失敗時は、この要求で新規作成したAuthアカウントのみ取り消す。取消失敗はエラーで案内する。パスワード・合言葉はDBプロフィール・監査ログ・レスポンスへ保存しない。

## 検証と残課題

テスト24件・型チェック・Lint・本番ビルドが成功。Critical対象の初回制限・権限・競合を優先して確認した。入力バリデーション、初回1件制限、担当者の登録拒否、匿名・通常認証ロールのRPC拒否、revision競合、監査ログをローカルDBで検証済み。実環境のキー設定、追加SQL適用、実アカウント作成・ログインは利用者の設定後に確認する。
前回2ファイルはユーザー報告で実行済み。旧設定手順にあるAuth画面・UUIDによる手動登録は、この追加画面で置き換えられる。

参考: [Supabase Auth Admin createUser](https://supabase.com/docs/reference/javascript/auth-admin-createuser)、[API keys](https://supabase.com/docs/guides/getting-started/api-keys)。
