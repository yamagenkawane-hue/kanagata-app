# CPU高負荷の復旧確認

## 適用と復旧の証拠
ユーザー提供のSQL結果で `app_private.lock_revision(bigint)` に `PT409` が含まれること（fix_applied=true）を確認。ユーザーがSupabaseプロジェクトを再起動した。

再起動直後の画像ではUnhealthy・CPU100%。その後の画像でHealthy・CPU80%、最新画像でHealthy・CPU2%、RAM49%、接続6/60、表示範囲Last60minutesのTotalRequests3・SuccessRate100%を確認した。再起動直後には、読み取り専用HEAD要求がHTTP200で応答することも確認済み。

PT409への修正と再起動後に高負荷が収束したことは、PostgREST14の40001内部再試行問題との整合性が高い。CPU低下はこれらの対処後の観測であり、先行した取得最適化だけの効果とは説明しない。全種類の業務操作が正常であることや長期的な再発防止を、この画像だけで保証しない。

## 先行説明の訂正
公式の最新説明では、修正前から実行中の再試行処理は関数修正だけでは停止せず、該当バックエンドの停止またはプロジェクト再起動が必要。本件ではユーザーによる再起動で対応した。先行文書の「接続強制終了は不要」は、進行中の再試行の停止が不要という意味で参照しない。

公式説明：https://supabase.com/docs/guides/troubleshooting/high-cpu-and-infinite-transaction-retries-when-using-custom-error-codes-in-rpc-functions-77326b
