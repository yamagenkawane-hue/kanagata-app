# 生産管理システム 要件定義書

版: 0.1（承認依頼）
作成日: 2026-09-30
フェーズ: requirements

## 1. 背景・目的

製品の細かいパーツごとに工程を計画し、設備・担当者・終了予定時刻をガントチャートで確認する。
飛び込みタスクにも対応し、優先順位に応じた日程調整と後工程への反映を自動化する。
予定と実績作業時間を分けて管理する。

## 2. 対象ユーザー

- 約10名。使用端末はPC。
- 管理者: 予定作成・調整、設備重複警告の確認と保存、飛び込みの挿入、変更後の日程確認。
- 工程担当者: 実績入力・修正。他の担当者の実績も入力・修正可能。

## 3. 管理対象・登録項目

- 登録項目: 製品名、パーツ名、数量、図番、顧客名、納期、備考。
- 管理番号と金型名は入力項目にしない。内部の識別方法は設計で決定する。
- 各パーツの工程タスクに設備・担当者・所要時間・予定日時・実績を関連付ける。
- 工程順: マシニング → 自動研磨 → ワイヤー → 型組 → トライ。
- 工程の省略・繰り返し・順序変更は行わない。

## 4. 必須機能（Must）

### 4.1 ガントチャート

- 提示画像を参考に、左側の一覧と右側の時間軸を組み合わせる。
- 日付を表示し、時間を30分単位で扱う。
- パーツごとの工程タスク、設備、担当者、終了予定時刻を確認できる。
- 工程ごとに色分けし、優先順位と重複警告を表示する。

### 4.2 予定の自動計算

- 設備ごとに予定を管理する。
- 各工程の所要時間から固定順の5工程の日程を自動計算する。
- 所要時間は設備・工程の稼働時間として計算する。
- 通常は会社カレンダーと勤務時間を使用する。
- 設備重複は優先順位に従って空き時間へずらして回避する。
- 管理者は計算後に手動調整できる。
- 手動変更で設備が重複する場合は警告し、管理者が確認すると保存できる。

### 4.3 優先順位・飛び込み対応

- 優先順位は1・2・3…の順番で指定する。
- 飛び込みタスクを順番の途中に挿入できる。
- 挿入と順位変更に応じて後工程の日程も自動調整する。
- 自動調整は未着手タスクのみ対象とし、作業中・完了済みと実績は維持する。
- 変更後の日程と納期超過を表示し、管理者の確認後に保存する。

### 4.4 会社カレンダー・稼働時間

- 会社カレンダーで稼働日・休日をすべて設定する。
- 勤務時間: 8:50〜17:40。
- 昼休み: 12:00〜12:50。休憩: 15:00〜15:10。
- 通常の実働時間: 1日7時間50分。
- 設備は休憩中も動かせる。
- マシニング・自動研磨・ワイヤーはタスクごとに夜間稼働を指定できる。
- 夜間稼働を指定したタスクは日付をまたぎ、休憩・夜間・会社休日も継続できる。

### 4.5 実績

- 状態: 未着手・作業中・完了。
- 実際の開始・終了と、日ごとの作業時間を記録する。
- 作業開始・終了時刻から休憩を除いて時間を自動計算する。
- 計算結果は必要に応じて修正できる。
- 進捗率（％）は設けない。

## 5. 補助機能の提案（Should / Could）

- Should: 自動計算前後の日程比較、保存前の取消、設備・担当者・製品による絞り込み。
- Could: 日・週などの表示期間切替、工程詳細のクリック表示、ドラッグによる予定調整。
- 在庫・購買・原価管理、スマホ専用画面は今回の要求に含めない。

## 6. 非機能要件の提案（承認対象）

- 管理者・担当者の権限を画面と保存処理の両方で制御する。
- 個人アカウントでログインし、予定は全員が閲覧できる。
- 実績変更時に更新者・更新時刻を記録する。
- 複数の利用者による変更を、気付かず上書きしない仕組みを設ける。
- 自動調整の確定は関連タスクをまとめて保存し、途中だけ反映された状態を避ける。
- 日時の基準は日本時間とする。
- 業務データはSupabaseへ保存する。接続先と公開先は別途確認する。

## 7. 設計時に確認する詳細（未確定・非ブロッキング）

下記は本書の要望整理を妨げないが、該当する設計・実装前に確認する。推測で確定しない。

- ログイン方式、管理者によるアカウント作成・管理方法。
- 登録項目の必須・任意、製品とパーツの所属・数量の扱い。
- 30分単位と8:50・17:40・休憩境界との関係。境界時刻を指定可能にする案。
- 同じ設備の順位の振り直し方法、同順位の扱い、再計算の範囲。
- 手動で重複許可した予定を、次回の自動調整でも維持するか。
- 夜間指定がないタスクの休憩中稼働の指定方法。
- 担当者の時間重複、無人稼働時間と担当者の実績の分離、日またぎ実績の分割。
- 実績時間を修正した場合の理由入力。
- ガントの初期表示期間、予定と実績の表示方法。
- Supabase接続先、公開先、既存データ移行、バックアップ運用。
- データ量と同時利用条件に応じた応答時間の目標。

## 8. 代表的な受入確認

1. 通常工程の予定が休憩・休日をまたぐと、稼働可能時間へ正しく繰り越される。
2. 夜間指定タスクが休憩・夜間・休日をまたいで継続する。
3. 飛び込みを途中へ挿入すると優先順位が反映され、設備の後続予定と依存する後工程が調整される。
4. 自動調整で作業中・完了済みのタスクと実績が変わらない。
5. 変更後の日程と納期超過を確認してから保存できる。
6. 管理者は設備重複警告を確認して重複予定を保存できる。
7. 実績11:30〜13:20は昼休み50分を除いて60分となり、修正もできる。
8. 担当者が他の担当者の実績を入力・修正できる。

## 9. 進行状況

- 実施内容: ヒアリング結果の整理と初期開発範囲の提案。
- 成果物: 本書、requirements-notes.md、要件整理案.md。
- 差し戻し: なし。前工程の業務成果物は存在しない。
- 次工程: 本書の承認後にdesignへ進み、未確定事項を該当設計前に解消する。
- 本書は承認前であり、業務機能の実装は未着手。
