# Supabase初期設定と操作手順（2026-10-01）

## 現在の状態

DB画面、BOM、ページ遷移、保存API、数量・権限・更新競合を検証するSQLを実装した。
2026-10-01のリモート読取確認ではprofilesとbom_itemsは未作成（404 / PGRST205）。以下の適用はまだ実施していない。管理画面の読取SQLではAuthユーザー数0件を確認した。
環境変数の接続URL・Publishable keyだけでは、テーブル作成や管理者登録はできない。

## 1. SQL適用

Supabaseのkanagata-appプロジェクトのSQL Editorで、次の順序で実行する。

1. `supabase/migrations/202609300001_initial_schema.sql`
2. `supabase/migrations/202610010001_bom_and_mutations.sql`

初期SQLは新規テーブル専用。既に適用しているSQLは繰り返し実行せず、DBの状態を確認する。
両SQLはトランザクション内で作成し、エラー時にはそのSQLの変更をロールバックする。テーブル作成と権限変更を含むため、適用対象を確認してから実行する。
ローカルでは同じSQLをPostgreSQL互換ランタイムで実行検証済み。

## 2. 最初の管理者

Authentication → Usersでメール・パスワードのログインアカウントを作成する。パスワードは利用者自身が入力し、チャットやGitに残さない。メール招待を自動送信する処理は実装していない。
作成した利用者UUIDを指定して次をSQL Editorで実行する。

```sql
-- 実際のUUIDに置き換える。最初の管理者1名を登録する。
insert into public.profiles(user_id, display_name, role)
values ('AUTH_USER_UUID'::uuid, '管理者', 'admin');
```

担当者の追加はAuthアカウントを作成した後、アプリのユーザー設定でUUIDを指定して利用者を登録できる。担当者のroleはoperator。
以降の表示名・役割・利用可否はアプリのユーザー設定画面で管理する。最終管理者の降格・停止は禁止する。

## 3. ログインとテストデータ

1. `/login`でログインする。
2. `/workspace/products`などの管理画面で「初期セットアップ・テストデータ」を開く。
3. 「テストデータを登録」を押し、内容を確認して実行する。
4. テスト金型2件、BOM4項目、テスト設備10台（ワイヤー4台）、約180日の架空カレンダー、プレート製作ロット2件・予定10工程を作成する。
5. ガントで予定を確認する。テスト部品は必要数量4、対象工程はマシニング・ワイヤー・型組。数量分割を確認できる。

テストデータは既存データを消さず追加する。カレンダーの既存設定は上書きしない。KPLAN_TEST_SEED_V1の目印が既にある場合は再登録を拒否する。
担当者は実際に登録したAuthプロフィールを使う。テスト用パスワードや架空Authアカウントは自動生成しない。

## 4. 基本操作

- 金型管理: 製品名・取引先・納期・備考を登録する。
- BOM: 金型にプレート・パーツを登録する。プレートは5工程、パーツは必要工程を選択する。
- 予定: ガントの「BOMから予定を追加」で金型・項目・製作数量・工程条件を入力する。未登録数量以内で分割できる。
- 確定: 再計算プレビューで変更前後と納期超過を確認して保存する。
- 詳細: 工程名から工程別、機械名から機械別ガントへ移動する。編集ボタン・バーから予定と実績を編集する。
- 実績: 担当者は他の担当者の実績も入力・修正できる。実績削除は管理者のみで履歴を残す。
- 非表示: 金型・BOM・ロットを非表示にする。作業中・完了済みロットは取消不可。未着手ロットの取消は数量枠を戻す。
- 設備: 使用停止できるが、未完了の有効な予定がある設備は停止できない。
- Excel: 会社カレンダーでテンプレートを取得。「日付」「稼働日」列のxlsxを選択し、プレビュー後に保存する。稼働日は1／0または稼働／休日。先頭シート・2000日以内・ファイル1MB以内。

会社の既存Excel形式は未確認。標準テンプレート形式に先行対応し、異なる列形式はエラーで案内する。定期自動取り込みは行わない。

## 5. エラー・運用

「他の利用者が更新しました」は再読み込みしてから再入力する。古い画面のまま上書きしない。
勤務条件変更・実績・取消後は、管理者が再計算して日程を確定する。
デモは`/demo`。DB画面は`/workspace`。ログイン・テーブルが未設定のとき、デモを実データとして表示しない。
本番配備はHTTPSと正しいAuth設定を使用する。LANのHTTP開発画面は`npm run dev -- --hostname 0.0.0.0`で起動する。
