# 要件整理案：生産計画・実績管理

更新日: 2026-09-30
フェーズ: requirements（確認中）
この資料は確認済み要望と提案を整理したものです。最終の要件定義書・設計書ではありません。

## 目的・利用者

PCで製品・パーツ別の工程予定と実績を管理し、設備の空き時間とタスクの終了予定時刻を確認できるようにする。
利用者は約10名。管理者が予定を作成し、工程担当者が実績を入力する。
担当者は他の担当者の実績も入力・修正できる。

## 確認済みの機能（初期開発で必須とする案）

| 機能 | 内容 |
| --- | --- |
| 登録項目 | 製品名、パーツ名、数量、図番、顧客名、納期、備考。管理番号・金型名は不要 |
| 固定工程 | マシニング → 自動研磨 → ワイヤー → 型組 → トライ。省略・繰り返し・順序変更なし |
| 予定 | 設備・担当者を設定し、所要時間から5工程の日程を自動計算 |
| ガント | 日付を表示し、30分単位でパーツごとのタスクと終了予定時刻を確認 |
| 優先順位 | 1・2・3…の順番を指定し、飛び込みタスクを間に挿入可能 |
| 自動調整 | 優先順位に従って設備の空き時間へ配置し、飛び込み挿入時は後工程も調整 |
| 重複予定 | 管理者は警告を確認して手動で重複予定を保存可能 |
| 会社カレンダー | 稼働日・休日をすべて設定 |
| 実績 | 未着手・作業中・完了、開始・終了、日別の作業時間を記録。進捗率なし |
| 時間計算 | 実績の開始・終了時刻から休憩を除いて計算し、必要に応じて修正可能 |

## 稼働時間

- 通常勤務: 8:50〜17:40。
- 昼休み: 12:00〜12:50。休憩: 15:00〜15:10。
- 通常の実働時間: 1日7時間50分。
- 通常の工程所要時間は勤務時間と会社カレンダー内で計算。
- 設備は休憩中も稼働可能。
- マシニング・自動研磨・ワイヤーはタスクごとに夜間稼働を指定でき、休憩・夜間・会社休日も継続可能。
- 設備の無人稼働時間を担当者の実績作業時間として扱うかは、別途確認する。

## 飛び込みの操作例（提案）

同じ設備の予定が「A（1位）→B（2位）→C（3位）」の場合、飛び込みXを2位へ挿入する。
順番を「A（1位）→X（2位）→B（3位）→C（4位）」へ更新し、B・Cの予定を再計算する。
B・Cの後工程にも変更を反映し、他の設備に重複が生じる場合はその設備の順番も考慮する。
新しい予定と納期超過を確認してから管理者が保存する。
保存前の変更は取り消せる。

## 自動調整について確認中

- 未着手のみを移動し、作業中・完了済みと実績は維持する（確認済み）。
- 変更後の日程と納期超過を管理者が確認してから保存する（確認済み）。
- 手動で重複を許可した予定を、次回の自動調整で維持するかは未確定。

## その他の未確定事項・提案

- ログイン方式と予定の閲覧範囲。
- 登録項目の必須・任意の区分。
- 30分単位の操作に加え、8:50・17:40・休憩境界の時刻を指定可能にする案。
- 休憩中の稼働を、夜間稼働とは別に指定できるようにする案。
- 実績の修正理由・変更履歴。
- 担当者の予定重複を警告するか。
- ガントの表示期間、予定と実績の表示方法、絞り込み。
- Supabaseの接続先、公開先、既存データの移行。

## 開発範囲の整理案（MoSCoW）

- Must: 上記の確認済み機能。各タスクの日程自動計算と飛び込み対応。
- Should: 日程変更のプレビュー、納期超過の表示、変更取消。
- Could: 表示期間切替・絞り込みの詳細は画面設計時に確認。
- 今回の要求なし: 在庫・購買・原価管理、スマホ向け画面。

## 確認に使う代表ケース

1. 通常タスクが昼休み・午後休憩・会社休日をまたぐ場合、所要時間が正しく繰り越される。
2. 夜間指定タスクは休憩・夜間・休日をまたいで継続する。
3. 飛び込みを2位に挿入すると、同設備の後続タスクと依存する後工程が再計算される。
4. 管理者は設備重複警告を確認し、重複した予定を保存できる。
5. 11:30〜13:20の実績は昼休み50分を除いて60分となり、必要に応じて修正できる。
6. 工程担当者が他の担当者の実績を入力・修正できる。
