# ガント機械別表示と遅れ自動調整（2026-10-14）

## 確定要件と実装

- 機械の空き時間を優先して確認できる機械別表示を初期表示にし、金型別表示へ切り替え可能。工程順はマシニング、自動研磨、ワイヤー、型組、トライ。追加工程は既存カタログ順を維持。
- 同じ機械の複数金型・パーツを同じ時間軸にまとめ、重なる場合のみ補助行を使用。登録済みの稼働設備は予定がなくても空き行を表示（絞り込み時を除く）。
- 時間表示は30分目盛り、初期横位置は8:00。3日・1週間表示も選択できる。
- 背景の横ドラッグは横スクロール。バーの横ドラッグは従来どおり30分単位の予定変更。加工順変更と後続繰り下げを選択でき、後工程へ連動。手動操作はまとめて確認・保存し、確認画面は変更対象だけを表示。
- 未着手で実績がなく予定終了を過ぎた工程を、1時間ずつ繰り下げた開始希望から再計算。終了が現在より後になるまで必要な回数を調整する。
- 会社カレンダー、休憩、勤務時間、機械の空き時間、工程依存、夜間稼働を適用。同じ金型の後工程と同じ機械で影響する他金型も再計算し、元の予定より前に戻さない。
- 作業中・完了済み・固定予定・実績開始または実績ログがある予定は維持。維持した予定と両立できない場合は保存せずエラーを表示。

## 自動保存と安全な競合処理

管理者が計画画面を開いたとき、その後1時間ごとに処理する。画面を閉じている間は実行しない。工程担当者からの自動保存は行わない。

DBモードは既存GET APIで最新データを取得し、その改訂番号で既存の予定保存RPCを呼ぶ。変更がなければ保存しない。追加SQLは不要。デモは画面内だけで変更を保持し、再読み込みで消える。

フォーム・実績編集・プレビュー・手動変更の編集中や保存中は自動処理を延期する。変更数と納期超過の金型数を通知する。競合・取得失敗の直後に再試行しない。保存結果が不明の場合は既存の再読み込みによる確認を要求し、自動保存を止める。通常の失敗は次の1時間後の確認対象となる。

既存の手動重複が保存検証に抵触する場合も自動で重複を許可せずエラーとする。CPU高負荷対策として導入した非再試行エラーPT409を維持。

## 設計・変更ファイル

- `src/domain/overdue-plans.ts`：入力を変更しない遅れ計算、保護対象、変更判定。
- `src/components/planning/use-overdue-adjustment.ts`：管理者限定タイマー、最新取得、改訂番号を用いた保存、通知。
- `src/components/planning/pan-scroll.tsx`：背景ドラッグと時間表示の初期位置。
- `planning-board.tsx` / `machine-rows.tsx`：表示切り替え、設備の空き行、金型・パーツのバー名。
- `src/lib/business/client.ts`：既存の時間制限付き通信にGET対応を追加。
