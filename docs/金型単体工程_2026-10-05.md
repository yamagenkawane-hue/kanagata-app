# 金型単位の型組・トライ（2026-10-05）

## 要件

Must: 型組・トライはプレートや部品のBOMに含めず、金型単位の独立予定として登録する。BOMの加工工程はマシニング・自動研磨・ワイヤーのみ。プレートは3加工工程すべて、パーツは必要な加工工程を選択する。型組・トライの所要量は1日以上の整数日数（1日470分）を維持する。

## 設計・実装

生産計画画面の「＋ 型組・トライを登録」から、金型・工程・設備・担当者・日数・開始可能日時を入力する。BOMの名称や数量は選択しない。金型ごとに型組とトライをそれぞれ1件登録でき、登録済みはガントから編集する。ガントには「型組／トライ（金型単体工程）」と表示する。金型詳細の一覧から未着手工程の取消も可能。実績・権限・日程プレビュー・確定の方式は従来どおり。

型組は同じ金型に登録済みの全加工予定の終了後、トライは全加工予定と型組の終了後に配置する。完了工程は実際の終了時刻を使う。まだ登録されていない工程・BOM数量は待たないため、必要な加工予定を登録してから自動計算を確認する。追加の加工予定によって未着手の単体工程も再計算される。作業中・完了済み・固定予定は維持する。設備順位との循環や固定予定に間に合わない場合は従来同様エラーとして確認を求める。

既存の予定・実績を再利用するため、DBの`parts.scope`で`part`と`mold`を区別する。単体工程にはBOMを付けず、数量1・対象工程1件に制限。金型と工程の有効な組合せを一意にする。既存の`tasks`・実績テーブルを使用し、`commit_plan`で登録、`read_planning`で取得する。APIルートは追加しない。API・DBでもBOMからの新規工程登録を3加工工程に制限し、単体工程の整数日数・通常勤務条件・先行工程順序・管理者権限を検証する。

## DB適用と既存データ

これまでのSQLを適用後、`supabase/migrations/202610050004_mold_processes.sql`をSupabase SQL Editorで実行する。直前の`202610050003_task_days.sql`が未適用の場合は先に実行する。

BOMから型組・トライを除外する。加工工程を持たない旧BOM項目は削除せず非表示にする。既存の部品別予定と実績は保持し、画面では「旧部品別」と表示する。新しい金型単位の予定への自動統合・実績の付け替えは行わない。旧予定が不要な場合、未着手のロットは取消できるが、作業中・完了済みのロットは履歴として残す。旧部品別タスクと新しい単体工程を併用すると両方が表示・計算されるため、実際に必要な予定を確認して登録する。
